# Data dictionary

Original archives (read-only, never modified) live in
`../project data/dataset` (configurable via `INVENTORY_DATA_DIR`).
**Note:** the folder is named `dataset` (singular), not `datasets` as in the original brief.
`scripts/extract_data.py` copies their contents into `data/raw/<dataset>/` (manifest: `data/raw/extraction_manifest.json`).

| Archive | Extracted to | File | Source (identified from contents) |
|---|---|---|---|
| `Retail Transactions and Stocks Data.zip` | `data/raw/mendeley_retail_transactions_stocks/` | `retail_sales_ml_apl.csv` (39 MB), `retail_inventory_ml_apl.csv` (100 MB) | Mendeley Data — "Retail Transactions and Stocks Data" |
| `archive (1).zip` | `data/raw/kaggle_sales_data/` | `sales_data.csv` (6.3 MB) | Kaggle (retail store inventory/demand dataset, variant with `Demand`, `Epidemic`) |
| `archive (2).zip` | `data/raw/kaggle_retail_store_inventory/` | `retail_store_inventory.csv` (6.2 MB) | Kaggle "Retail Store Inventory Forecasting" dataset (variant with `Demand Forecast`) |

No README, licence file or data dictionary was included in any archive. **Licence and exact
citation must be taken from the original Kaggle / Mendeley pages before publication** (Mendeley
Data is usually CC BY 4.0, which requires attribution; Kaggle licences vary by dataset). The
archives carry no author or URL metadata, so these could not be verified offline.

Column names are standardized to snake_case **in memory only** (`inventory_rl.data.loaders.snake`).

## Mendeley — `retail_sales_ml_apl.csv` (primary; 125,751 rows)

| Column | Type | Meaning / observation |
|---|---|---|
| Transaction Date | date `YYYY-MM-DD` | 2025-06-01 … 2026-04-24 (326 distinct days) |
| Sales Type | category | Full Price, Promo, Markdown Tier 1/2, Clearance |
| Is Return | 0/1 | 1 ⇔ `Qty Sold` < 0 (7,491 rows; consistent in all rows) |
| Reason of Return | — | entirely empty |
| Supplier | id | `Vendor 0xxx` |
| Product No | id | SKU id `PROD-xxxxxx` (2,326 SKUs) |
| Product Description | text | contains another PROD id + segment + names (anonymized) |
| Product Division / Category / Subcategory / Segment | hierarchy | 3 divisions, 27 categories, 51 subcategories, 600 segments |
| Store | id | `STR-1xxx` (40 stores) — **no address or coordinates** |
| Sales Channel | constant | single value `Channel Alpha` |
| Qty Sold | float | units (negative for returns); range −3 … 14 |
| Sales Amount, Cogs | float | revenue and cost of goods sold (negative for returns) |
| Number of Transactions | int | 1 … 14 |

## Mendeley — `retail_inventory_ml_apl.csv` (primary; 284,755 rows)

Slowly-changing-dimension style **validity intervals** of stock on hand.

| Column | Type | Meaning / observation |
|---|---|---|
| Start Date, End Date | date | record valid on [start, end]; `9999-12-31` = current/open record (22,701 rows) |
| Stock Status | category | Full Price, Markdown Tier 1/2, Clearance, Promo (one SKU can have several pools at once) |
| Supplier, Product No, Product Description, Product Division … Segment, Store | ids | as in sales |
| Store Type, Sales Channel | constant | `Retail Storefront`, `Channel Alpha` |
| Qty on hand | int | −9 … 56; 1,380 negative (book-stock errors), 13,869 explicit zeros |
| Stocks Selling Amount, Cost of Stocks, Stock Unit Selling Price, Stock Unit Cost Price | float | valuation of the stock record |

## Kaggle — `sales_data.csv` (76,000 rows) and `retail_store_inventory.csv` (73,100 rows)

`Date, Store ID (S001–S005), Product ID (P0001–P0020), Category, Region, Inventory Level, Units Sold,
Units Ordered, Price, Discount, Weather Condition, Promotion / Holiday-Promotion, Competitor Pricing,
Seasonality` plus `Epidemic, Demand` (sales_data) or `Demand Forecast` (retail_store_inventory).
Daily, 2022-01-01 to 2024-01-30 / 2024-01-01. See `data_audit.md` for why they are not used as the primary data.

## Processed artifacts (`data/processed/`, regenerated by the scripts)

| File | Grain | Key columns |
|---|---|---|
| `panel.parquet` | store × SKU × week (Mon–Sun) | `gross_qty` (units sold excl. returns), `return_qty`, `net_qty`, `promo_share`, `opening_stock`, `closing_stock` (NaN = no stock record), `closing_book_stock` (incl. negatives), `receipts_est`, `stock_recorded`, `split` |
| `features.parquet` | same | `f_*` features (lags 1,2,3,4,8; rolling mean/std 4,8; expanding mean; weeks since sale; lagged promo share; opening stock; cover; lagged SKU/store totals; week of year; month; store/SKU codes) |
| `unit_economics.csv` | SKU | observed training-period `unit_price`, `unit_cost` (COGS/unit), `unit_margin` |
| `forecasts.parquet` | store × SKU × week (from 2025-07-28) | `y`, `yhat`, `q_lo`, `q_hi`, baselines, `lo_/hi_{poisson,qr,cqr,conformal}`, selected `lo`, `hi` |
| `risk.parquet` | same | `p_stockout`, `expected_shortage`, `shortfall_upper`, `excess_units`, `surplus_point`, `surplus_upper`, `cover_weeks`, `risk_class` |
